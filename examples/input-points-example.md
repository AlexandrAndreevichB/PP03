# Пример: реестр точек ввода данных

> Учебный пример на **вымышленном** проекте «Запись в автосервис» (Vue + Laravel).
> Как проверяли: клиент — атрибуты формы и код компонента; сервер — `$request->validate(...)` в контроллере или класс FormRequest.

| № | Точка ввода | Поля | Проверка на клиенте | Проверка на сервере | Риск |
|---|---|---|---|---|---|
| 1 | Регистрация → `POST /api/register` | name, phone, password | да: `required`, маска телефона | да: `RegisterRequest` — `required`, `regex` для телефона, `min:8` | низкий |
| 2 | Свободные окна → `GET /api/slots?date=&service_id=` | date, service_id | да: календарь не даёт выбрать прошлую дату | частично: `service_id` — `exists`, `date` — не проверяется | средний: запрос на дату 1900 г. или `date=abc` даёт ошибку 500 с трассировкой |
| 3 | Запись → `POST /api/bookings` | slot_id, car_model, comment | да: `required`, `maxlength="500"` у комментария | частично: `slot_id` — `exists`, занятость окна проверяется; `comment` — нет | средний: комментарий любой длины, хранится без ограничения |
| 4 | Отмена записи → `DELETE /api/bookings/{id}` | id | — | да: `$this->authorize('delete', $booking)` | низкий |
| 5 | Фото повреждения → `POST /api/bookings/{id}/photo` | file | да: `accept="image/*"` | да: `image`, `max:5120` | низкий |
| 6 | Цена услуги (админка) → `PUT /api/services/{id}` | price | да: `type="number" min="0"` | **нет** | средний: отрицательная цена через запрос в обход формы |
| 7 | Отметка «выполнено» (мастер) → `POST /api/bookings/{id}/done` | — | кнопка видна только мастеру | да: middleware `role:mechanic` | низкий |

Итого точек: 7, без серверной проверки (полностью или частично): 3 — № 2, 3, 6.

Самые рискованные — № 6 (бизнес-данные меняются в обход ограничений формы) и № 2 (ошибка сервера раскрывает внутреннее устройство).

## Первый день (03.11)

1. Инструктаж по ТБ, подпись в карточке.
2. Установите программы из [docs/software.md](docs/software.md).
3. Скачайте этот репозиторий: `git clone <ссылка>` или кнопка Code → Download ZIP.
4. Сделайте форк учебного проекта **«Библиотека КАИТ»** (`kait-library`, ссылку даёт руководитель). В форме Fork **снимите галочку *Copy the main branch only*** — нужны все ветки. Клонируйте **свой** форк в папку веб-сервера (XAMPP: `C:\xampp\htdocs`). Свой проект вместо учебного — только по согласованию с руководителем 03.11.
5. Скопируйте шаблоны практики в свой проект (существующие файлы не перезаписываются):
   ```
   Windows:      tools\install.cmd C:\путь\к\вашему\проекту     (или перетащите папку проекта на install.cmd)
   Linux/macOS:  bash tools/install.sh ~/путь/к/вашему/проекту
   ```
6. Закоммитьте и отправьте:
   ```
   cd путь/к/вашему/проекту
   git switch -c practice/m01
   git add practice .github
   git commit -m "chore: add practice skeleton"
   git push -u origin practice/m01
   ```
7. Отправьте руководителю: ФИО, название проекта, ссылку на форк.
8. Впишите ФИО, проект и ссылку в бланк `docs/Документы_практики_ПП03.docx`, сохраните себе.
9. Начинайте [модуль 1](modules/m01.md).

**Проект практики:** по умолчанию — «Библиотека КАИТ» у всей группы (сценарии М2 — по вариантам, см. методичку). **Свой проект** (по согласованию 03.11): клиент + сервер + база данных; не менее 1500 строк кода, 30 коммитов и README; запускается на вашем компьютере; два студента не могут взять один и тот же свой проект.

## Как работать над модулем

```
git switch main                                # основная ветка
git pull                                       # обновить
git switch -c practice/m02                     # ветка модуля
# … работа, коммиты по ходу (не одним коммитом в конце!) …
git push -u origin practice/m02
# Pull Request practice/m02 → main, заполнить шаблон, влить
```

## Как сдать модуль

1. Проверка готовности (запускать из папки `pp03-ispo332`):
   ```
   python tools/check_practice.py путь/к/проекту --module 1
   ```
   Скрипт покажет, каких файлов нет, где остались `TODO`, есть ли отчёт и коммиты.
2. Отчёт: скопируйте `report-templates/report-M01.docx` как `ISPO332_Familiya_M01.docx` (фамилия латиницей), замените серые подсказки своим текстом, вставьте скриншоты.
3. Положите отчёт в `practice/m01/`, закоммитьте, влейте Pull Request, отметьте модуль в `practice/README.md`.

## Скрипты

Нужен Python 3.8+, сторонние библиотеки не нужны. Путь к проекту — аргументом.

| Скрипт | Что делает |
|---|---|
| `tools/install.ps1`, `tools/install.sh` | копирует `practice/` и `.github/` в проект |
| `tools/setup_kait.cmd` | Windows + XAMPP, PowerShell не нужен: создаёт базу из `database/`, `.env`, запуск из VS Code по F5 и может сразу запустить сайт. Двойной щелчок или перетащить на него папку проекта; MySQL в XAMPP должен быть запущен |
| `tools/setup_kait.ps1` | то же через PowerShell, дополнительно понимает OpenServer и добавляет PHP в PATH |
| `tools/install.cmd` | то же, что `install.ps1`, но без PowerShell: двойной щелчок или перетащите на него папку своего проекта |
| `tools/repo_stats.py` | авторы, ветки, теги, частота изменений файлов, активность, объём кода |
| `tools/metrics.py` | строки кода по языкам (сложность — если установлен `pip install lizard`) |
| `tools/check_practice.py` | проверка готовности модуля перед сдачей |
| `tools/php/phpcs.phar`, `phpcbf.phar` | М4: проверка и автоисправление стиля PHP по `phpcs.xml` проекта: `php ПУТЬ\tools\php\phpcs.phar` из корня проекта |

```
python tools/repo_stats.py C:\projects\library --out C:\projects\library\practice\m01\repo-stats.md
python tools/metrics.py C:\projects\library
```

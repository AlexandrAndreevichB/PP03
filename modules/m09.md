# Модуль 9. Отработка технологии code review

**18 ч · 24.11–26.11.2026 · ПК 3.2, ПК 3.3, ПК 3.4**

**Практическая тема:** изменение характеристик кода в различных средах разработки. Примените приёмы М03 к сценарию из М08. Используйте настройки М04, набор характеризационных проверок М08 и стандарт видео-багрепорта М07, если в Issue нужно видео.

### 24.11 · 5 ч. Подготовка и замер

После вливания М08 откройте один и тот же форк в VS Code и второй среде. Для PHP используйте PhpStorm или Apache NetBeans с поддержкой PHP. Для своего проекта возьмите две среды с поддержкой языка. В примере выбран возврат книги. Подставьте свой файл и путь к ПП.03. Если папки М09 ещё нет, сначала запустите `tools/install.cmd` из ПП.03 для своего форка.

```powershell
git switch main
git pull --ff-only
git switch -c practice/m09
$base = git rev-parse HEAD
$pp03 = 'C:\projects\PP03'
$target = 'src/LoanService.php'
python -m pip install lizard
python "$pp03\tools\metrics.py" . --label 'М09 до' --out practice/m09/metrics-raw.md
python -m lizard -l php $target
git ls-files --eol -- $target
```

Запишите SHA, версии IDE и расширений, настройки, CCN и NLOC выбранной функции, отступы, EOL, результат синтаксической проверки или линтера. Для замеров «до» и «после» используйте одинаковые инструменты, область и правила. Заполните в `metrics.md` сравнение навигации, переименования, выделения метода, форматирования и диагностики в двух IDE.

### 25.11 · 9 ч. Изменения и контроль

1. Переименуйте локальный символ в первой IDE. Во второй выделите связный блок в функцию или метод. Для каждой операции проверьте предварительный просмотр, параметры, возвращаемое значение и область видимости. Если в IDE нужная операция недоступна, запишите ограничение и используйте для неё вторую IDE, а в первой выполните другую операцию с кодом.
2. Сверьте форматирование с правилами М04. Если нужны правки пробелов или окончаний строк, оформите их отдельным коммитом. Работайте в выбранном фрагменте и проверьте `git diff --check`.
3. Повторите все исходные случаи М08 на одинаковых данных. Для операций записи восстановите исходное состояние перед каждым прогоном. Сверьте ответ, сообщение, значения и изменения данных. При расхождении исправьте свой рефакторинг и повторите проверку.

```powershell
php -l $target
python -m lizard -l php $target
git ls-files --eol -- $target
git diff --check $base
python "$pp03\tools\metrics.py" . --label 'М09 после' --out practice/m09/metrics-raw.md
```

Для PHP проведите PHPCS на целевом файле с теми же правилами М04. В своём стеке используйте соответствующие команды. Запишите результаты целевого фрагмента в `metrics.md`, включая новые методы. В `regression.md` сопоставьте все случаи «до» и «после». Сделайте отдельные коммиты рефакторинга и сохраните промежуточные результаты в `practice/m09`, чтобы история показывала ход работы.

### 26.11 · 4 ч. Перекрёстное ревью и сдача

1. Откройте PR `practice/m09 → main`, приложите базовый SHA, ссылки на М08, метрики и способ проверки. Обменяйтесь PR с одногруппником. Проверьте его код по `review.md`: малый diff, параметры и результаты, покрытие ветвей, побочные эффекты, стилистика. Оставьте комментарий к конкретному месту и отправьте итог ревью. Ответьте на полученные замечания и повторите затронутые проверки после правок.
2. Заведите Issue на подтверждённую функциональную находку или конкретный пробел в проверках. Укажите версию, шаги на учебных данных, ожидаемое и фактическое поведение, приложите доказательство. Если для воспроизведения нужно видео, используйте стандарт М07. Сохраните ссылки на Issue и входящее/исходящее ревью в `review.md`.
3. Перед финальным коммитом актуализируйте замер «после» и регрессию при изменении кода. Убедитесь, что в папке модуля нет незаполненных полей.

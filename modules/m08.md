# Модуль 8. Отработка технологии обратного проектирования алгоритма

**18 ч · 20.11–24.11.2026 · ПК 3.3**

Восстановите алгоритм одного сценария в своём форке по исходному коду и наблюдениям. Из М02 возьмите трассировку как отправную точку. В М09 повторите те же проверки после рефакторинга.

**Проект:** «Библиотека КАИТ» или согласованный проект. Для «Библиотеки КАИТ» выберите один сценарий.

| Сценарий | Где начинать | Граница исследования |
|---|---|---|
| Возврат книги | `public/assets/js/librarian.js` → `public/api.php`, `loan.return` → `src/LoanService.php`, `returnBook()` | Результат операции, состояние выдачи и экземпляра |
| Выдача книги | `public/assets/js/librarian.js` → `public/api.php`, `loan.issue` → `src/LoanService.php`, `issue()` | Решение о выдаче, срок и запись о выдаче |
| Список должников | `public/index.php`, `debtors` → `src/ReportService.php`, `debtors()` | Состав строк и итоговые суммы на странице |

Выполняйте команды из корня своего форка. `$pp03` в примерах — абсолютный путь к папке с материалами ПП.03.

```powershell
git switch main
git pull --ff-only
git switch -c practice/m08
$pp03 = 'C:\projects\PP03'
& "$pp03\tools\install.cmd" (Get-Location).Path
git rev-parse HEAD
```

1. **20.11 · 5 ч.** Запустите сценарий на локальных учебных данных. Зафиксируйте SHA исходного кода, окружение, входы и выходы. Проследите один обычный случай от интерфейса до реализации и результата. Запишите файлы и номера строк в `algorithm.md`.
2. **23.11 · 9 ч.** Прочитайте условия, циклы и ранние выходы. Запишите псевдокод. Постройте блок-схему и UML-диаграмму последовательности для того же сценария. Подпишите условия на стрелках, альтернативы укажите через `alt`, повторения через `loop`, если они есть. Экспортируйте обе схемы в PNG.
3. **24.11 · 4 ч.** Проверьте не менее пяти случаев в `characterization.md`: обычный, два граничных или альтернативных, отказ операции или пустой результат и ещё одну ветвь. Покройте ключевые ветви модели. Для каждого укажите исходные данные, шаги, ожидаемый по коду и фактический результат. Для записи в БД укажите состояние до/после и способ восстановления тестовых данных. Опишите расхождения между README, своим предположением и наблюдаемым поведением, если они обнаружены.
